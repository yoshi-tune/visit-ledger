# 人の承認つきのループ（月初のふり返りを1周させる仕組み）

> 2026-11-07 に作った。ナットク台帳で「DX 担当が毎月読み解かなくても、店長が月初のふり返りを回せる形」にするための仕組みと、ほかの業務のシステムに同じ形を持ち込む時に、どこを差し替えればよいかをまとめる。
> **自律して勝手に直り続ける仕組みではない。** 自動で進むのは「提案を作る」まで。提案の条件が分析の求めた対象と合っているかは人が確かめ、変えるのは必ず人が押した時だけ。受付での照らし合わせ・お客様への連絡も人の仕事のまま。分析のやり方の見直しは、このループの外に置いている。
> ほかのシステムに移したことは、まだ無い。下の「差し替える所」は、この作品の作りから見た見立て。

## ループの7段

```
① 台帳に記録 → ② アプリが数える → ③ Claude が分析（検算と採点つき）
 → ④ 次の一手を、決まった部品だけで受付の一覧（タブ）に提案（ここまで自動）
 → ⑤【人】分析が求めた対象と、提案の条件・一覧が合っているか確かめて「反映する」（合わなければ「やめる」）
 → ⑥ 受付で「送った・返事あり」「その日に来店・取消」を記録
 → ⑦ 次の分析が、前回の一手のその後を振り返る → ③ へ
```

| 段 | 何をするか | 誰が | 作っているファイル | 柵（何を止め、何は止めないか） |
|---|---|---|---|---|
| ① 記録 | LP の閲覧・予約・来店・クーポン・お知らせを1本の台帳に残す | お客様・受付 | `app/ledger.py`（読み書きはここだけ） | 押し間違いは取り消せ、取り消した記録も残す |
| ② 集計 | 施策ごとに LP → 予約 → 来店の数を数える | アプリ | `app/funnel.py` | 数えるのはコード。Claude には数えさせない |
| ③ 分析 | 台帳の書き出しを数え直し、見立てと次の一手を出す | Claude（Managed Agents） | `app/export.py`・`app/analysis/`・`agent/analyst_system.md` | 渡す列は許可した列だけ。報告は決めた形（`agent/report_schema.json`）でなければ失敗。アプリの集計と数え直しを照らす。採点の基準（`agent/rubric.md`）で最大3回書き直す。1回の上限額 |
| ④ 提案 | 次の一手を、受付のタブの条件に置き換える | ナットク（Claude）が自動で | `app/loop.py`（分析が終わった時に呼ぶ）・`app/maintenance.py`（部品と検査） | 条件の形を検査する：使えるのは決まった部品だけ（状態・来店予定日・来店予定日が過ぎた予約・予約から来店までの日数・メニュー・媒体）、値の範囲・組み合わせの矛盾はコードで捨てる。件数と一覧はアプリが数える。全体の上限額。**分析の意図と合っているか（対象を狭めすぎていないか）は検査しない** → ⑤ で人が確かめる |
| ⑤ 確かめて反映 | 分析が求めた対象と、提案の条件・一覧を見比べ、受付にタブを足すか決める | **人** | `app/main.py` の反映・取り消し・`app/static/maintenance.js` | 押さない限り何も変わらない。設定は版で残し、「さっきの変更を取り消す」で戻せる |
| ⑥ 実行の記録 | 受付でタブの予約に対応し、結果を押す | 受付 | `app/static/desk.js` | 実際には送らず記録だけ。押し間違いは取り消せる |
| ⑦ 振り返り | 前回の一手と、その時の数字を次の分析に渡す | アプリ → Claude | `app/analysis/__init__.py` の `_previous` | 数字の変化を一手の効果とは言わない（採点の基準で点検）。件数が少ないうちは「まだ判断できない」 |

**ループの外に置いているもの**
- 分析のやり方の見直し（`app/improve.py`・[IMPROVE.md](IMPROVE.md)）：答えの分かっている見本の台帳 A・B で試し、コードの決まりで残すか決め、本番に使うかは人が押す。毎月自動では回さない
- はじめの設定（置き場所・鍵・費用の上限）。新しい施策（チラシ・LINE の URL と QR）は、店長が店の設定の画面で足せる（11/7 夜に足した。`/api/campaigns`）
- 定期の起動はまだ無い：アプリの「今日」は見本のデータに合わせて 2026-11-07 に固定しているので、今は効果の画面の「月初のふり返りを回す」を人が押す。続けて使うには、ほかにも日付の固定を外すこと・店の人ごとの権限・失敗した時の対応・実際の店での確かめが残っている

## 公開 URL で確かめた区間（2026-11-07）：③ 分析 → ④ 自動の提案 → ⑤ 人の反映 まで

| 段 | 記録 |
|---|---|
| ③ 分析 | 分析 `an_6a6080af982e`（Opus 5.5・4分2秒・77セント）。次の一手：「来店未記録の23件について、作業伝票・レジの記録と照らし合わせ、来店していた予約は受付で来店を後から記録する」 |
| ④ 自動の提案 | 依頼 3（頼んだ人「ナットク（自動）」・Sonnet 5.5）。タブ「来店未記録(3日以上先)」：予約中・来店予定日が過ぎた予約（過去14日以内）・予約から来店予定日まで3日以上。アプリが数えて4件 |
| ⑤ 人の反映 | 作者が次の一手の画面で反映（担当 A）。設定の版 0 → 1。受付にタブが出て4件が並んだ |
| ⑥ 受付での記録・⑦ 次の分析の振り返り | **まだ確かめていない**（ここで止まっている） |

**この1周で分かったこと**：分析は「23件」を求めたが、提案は「過去14日以内」と「予約から3日以上」で4件に絞った。どちらの条件も部品の検査は通る（形は正しい）。対象を狭めすぎていないかはコードでは分からないので、⑤ で人が、分析の求めた対象と提案の一覧を見比べる。合わなければ反映せず、依頼の文を直して頼み直す。

## なぜこの形にしたか

- **数えるのはコード、読み解くのは Claude、変えるのは人**。Claude の文がもっともらしくても、数字はコードと照らし、変更は人の1押しでしか入らない
- **Claude に任せる所ほど、出せる形を狭くする**。報告は決めた形、提案は決めた部品の組み合わせだけ。自由に書かせるのは、人が読む文だけ
- **自動で進めるのは、取り消せる所まで**。提案は作っても反映しない。反映しても版で戻せる。記録は消さない
- **費用は2段で止める**。Anthropic Console のワークスペースの上限が本当の歯止め、アプリの上限はその手前

## ほかのシステムに持ち込む時

### 差し替える所

| 部品 | この作品では | 別の業務なら（例） |
|---|---|---|
| 台帳の形 | 閲覧・予約・来店・クーポン・お知らせ（`app/ledger.py` の SCHEMA） | 問い合わせ → 見積 → 受注、申込 → 審査 → 契約 など、その業務の段の記録 |
| 集計 | 施策ごとの段の数と来店率（`app/funnel.py`） | 段ごとの数と抜けた数 |
| 書き出しの許可した列 | `app/export.py` の ALLOWED と FORBIDDEN | 個人情報を落とした列の一覧 |
| 分析の手順書と採点の基準 | `agent/analyst_system.md`・`agent/rubric.md`（「来店未記録を来なかったと書かない」など） | その業務で言い過ぎになる言い方の一覧 |
| 提案の部品 | 予約の状態・来店予定日・来店予定日が過ぎた予約・日数・メニュー・媒体（`app/maintenance.py` の PARTS） | 現場の一覧を絞る条件（担当・段・経過日数など） |
| 実行の記録 | 送った・返事あり・その日に来店・取消 | 電話した・訪問した・返事あり など |
| 答えの分かっている見本 | 仕込みのある台帳 A・差の無い台帳 B（`scripts/make_sample.py`） | 本当の理由を1つ仕込んだ見本と、差の無い見本 |

### 再利用を想定する仕組み（ほかのシステムに移すのは未検証）

- 分析の呼び出しの形（Managed Agents で書き出しを数え直し、決めた形の報告を返す。予備として Messages API を1回呼ぶ形も、同じ報告の形で返す）
- 報告の形の検査・数え直しとアプリの集計の照らし合わせ・採点で書き直す回数の上限
- 提案 → 部品の検査 → 人が反映 → 版で残す・取り消す、の流れ（`app/loop.py`・`app/maintenance.py` の検査の作り）
- 前回の一手を次の分析に渡す形（`previous.json`）
- 公開する時の守り（ログイン・全体の上限・失敗の中身を出さない。`app/public.py`）

## まだ無いもの

- 時計で月初に起こす仕組み（上のとおり、今は人がボタンを押す）
- 店長・スタッフごとの権限（反映を店長だけにする、など）
- 実際の店での効果の確かめ
